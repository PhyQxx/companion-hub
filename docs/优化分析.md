## 1. P0-1 前端代码分割 + Element Plus 按需导入

### 问题与证据

- 构建产物单 JS chunk 1.7MB + CSS 471KB；`web/apps/vite.config.ts` 无 `build.rollupOptions.manualChunks`。
- `web/apps/src/main.ts` 全量 `use(ElementPlus)` 并引入全量 CSS，未用按需导入。
- `web/apps/src/router/index.ts` 三个入口（ChatRoot / AdminShell / ModuleWorkspaceView）全部静态导入。
- `ModuleWorkspaceView.vue` 把全部 43 个 admin 视图静态 `import` 进同一 chunk——聊天页用户也要下载整个后台。

### 具体方案

1. **路由懒加载**：`router/index.ts` 中入口组件改为 `component: () => import('../views/ChatRoot.vue')` 形式；ChatRoot 与 AdminShell 自然分成两个 chunk。
2. **admin 视图动态 import map**：`ModuleWorkspaceView.vue` 的视图映射表从静态对象改为 `defineAsyncComponent(() => import(...))` 或 `() => import(...)` 的惰性映射，保留键名不变，43 个视图各自成 chunk（Vite 会自动聚合）。
3. **Element Plus 按需导入**：接入 `unplugin-vue-components` + `unplugin-auto-import`（需确认本机 npm 私服/离线 store 可提供这两个包，见已知网络限制），删除 `main.ts` 的全量 `use(ElementPlus)` 与全量 CSS 引入。
4. **manualChunks 兜底**：对 `element-plus`、`echarts`（如有）等大依赖单独拆 vendor chunk，避免业务改动打爆缓存。
5. **验证**：`pnpm --dir web/apps build` 后用 `vite-bundle-visualizer` 或 `ls -la dist/assets` 对比首包（入口 chunk + 懒加载清单）体积；回归聊天页与 admin 各一个页面手测路由切换与弹窗组件渲染。

### 验收口径

- 入口 chunk（聊天首屏）显著小于当前 1.7MB 单文件；admin 视图按需加载（Network 面板可见切换 Tab 时才拉取对应 chunk）。
- `vue-tsc` typecheck 通过；既有功能手测无白屏/异步组件加载闪烁（必要时给 AsyncComponent 配 loading 占位）。

## 2. P0-2 Dockerfile web 构建层缓存与可复现构建

### 问题与证据

`Dockerfile` 第 4~5 行：

```dockerfile
COPY web ./
RUN pnpm install --no-frozen-lockfile && pnpm -r build
```

- 任何 web 源码改动都会使 `COPY web ./` 缓存失效，重跑全量 `pnpm install`。
- `--no-frozen-lockfile` 意味着构建时可能解析出与 lockfile 不同的依赖树，与 CI 的 frozen-lockfile 纪律矛盾（供应链不可复现）。

### 具体方案

```dockerfile
FROM node:22-bookworm-slim AS web-build
WORKDIR /web
RUN corepack enable
# 先只拷贝依赖清单与 workspace 骨架，install 层可被源码改动复用
COPY pnpm-workspace.yaml ./
COPY web/package.json web/pnpm-lock.yaml ./web/
COPY web/packages/*/package.json ./web/packages/
COPY web/apps/package.json ./web/apps/
RUN pnpm -C web install --frozen-lockfile
# 再拷贝源码并构建
COPY web ./web
RUN pnpm -C web -r build
```

（具体路径以 `pnpm-workspace.yaml` 声明的包为准核对；lockfile 位置以仓库实际为准——根目录或 `web/` 内。）

注意事项：

- 改动后先本地 `docker build` 验证缓存命中：改一个 `.vue` 文件重建，install 层应显示 `CACHED`。
- `--frozen-lockfile` 若因 lockfile 与 package.json 漂移而失败，属暴露既有问题，按错误提示重新 `pnpm install` 更新 lockfile 并单独提交，不要回退到 `--no-frozen-lockfile`。
- pnpm 的 store/挂载细节（如 `node_modules` 符号链接）在多阶段 COPY 中通常无需特殊处理，构建产物只取 `dist`。

### 验收口径

- 改 web 源码重建：`pnpm install` 层命中缓存；改 lockfile 重建：install 重新执行。
- 镜像内应用正常启动，compose 冒烟通过。

- 另有 `api/voice_ws.py` 2369 行、`api/device_commands.py` 1679 行、`cognition/action_plan.py` `execute_plan` 276 行。

### 具体方案

**不另立专项，挂在架构队列既有批次顺带做**（每批只动一个文件/一条路径，靠相关回归保护）：

1. **chat/service.py（结合 B-01 批次）**：

2. **路由工厂下沉（结合 A-01 领域迁移批次）**：

## 4. P1-2 ChatRoot.vue 拆分

### 问题与证据

`web/apps/src/ChatRoot.vue` 2137 行、setup 内 33 个 async 函数，同时承担：认证/登录、会话 CRUD 与归档、WebSocket 连接与重连（`connectSocket` 约 :1349，重连退避约 :1379-1388）、消息收发、语音链路、BroadcastChannel 主题同步（约 :1578）、会话导出、勾选模式、全局监听器。

### 具体方案

1. **先抽 composable（行为不变）**，按职责切：
   - `useChatSocket`：连接/重连退避/心跳/收发消息/onUnauthorized 订阅（改为返回 dispose，组件卸载时解绑）；
   - `useVoice`：语音链路状态与控制；
   - `useAuth`：登录态与 SSO 状态探测；
   - `useConversationExport`：导出与归档。
   - composables 放 `web/apps/src/composables/`，状态通过参数/返回值显式传递，不新建全局单例。
2. **再拆模板子组件**：聊天会话列表、消息区、输入区各自成 SFC，props/emits 显式连接；ChatRoot 退化为装配层（目标 ≤500 行）。
3. **ModelsView / SkillsView** 套用同一模式（列表 + 表单抽屉 + 轮询拆开），优先级低于 ChatRoot。
4. **风险控制**：纯机械搬移，不重构逻辑；每拆一个 composable 跑一次 `vue-tsc` + 浏览器手测聊天收发、断线重连、语音、主题切换四条路径。

## 5. P2 / P3 清单

### P2-1 启动分层并行

- 证据：`server/app/wiring/registry.py` `start_all()`（:92 起）按 `self.order` 逐个 `await self.start(name)`；`wiring/lifespan.py` 注册约 30 个调度器/循环，多数 `requires=("conversation",)` 互相独立却串行启动。
