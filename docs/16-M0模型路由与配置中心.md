# M0.5–M0.6 模型路由与配置中心

> 状态：已实现并纳入 CI。配置基线日期：2026-08-17。

## 1. 决策摘要

Companion Hub 不把业务逻辑绑定到某家模型。认知层只依赖 `CompletionRequest / CompletionResult`，供应商由 OpenAI-compatible 适配器封装，模型选择由 YAML 路由配置决定。

当前采用“商汤免费模型承担常规运行、GLM-5.3 Pro 辅助开发、私密数据只走本地”的组合：

| 场景 | 默认模型 | 备用模型 | 原因 |
|---|---|---|---|
| 日常陪伴对话、短问答、情绪化表达 | 商汤 `deepseek-v4-flash` | 商汤通道 `glm-5.2` | 对话质量优先，失败时允许切换较强推理模型 |
| 分类、摘要、记忆提取、标签生成、意图判断 | 商汤 `sensenova-6.8-flash-lite` | `deepseek-v4-flash` | 高频后台任务优先考虑速度与免费额度 |
| 较难规划、长链推理、复杂工具编排 | 商汤通道 `glm-5.2` | 人工确认后再扩展 | 只在确有难度时升级，避免所有请求都使用重模型 |
| 代码开发、架构分析、仓库级修改 | GLM-5.3 Pro（受支持编码工具内） | 当前开发模型 | Coding Plan 的强项和授权边界都指向编码场景 |
| L2 亲密语境 | 本地 `qwen2.5:7b` 占位配置 | 无云端备用 | 隐私优先；即使用户请求云模型也会被改路由 |
| L3 原始传感器/连续音视频 | 不调用 LLM | 无 | 在模型调用前阻断，不落日志正文 |

商汤实际可用模型会随账户和平台调整。2026-08-17 使用该账户的模型列表接口观察到 `deepseek-v4-flash`、`glm-5.2`、`sensenova-6.8-flash-lite` 等模型；上线前应重新探测，平台能力以[商汤日日新官方文档](https://platform.sensenova.cn/docs)为准。

## 2. GLM-5.3 Pro 的授权边界

GLM 官方把 GLM-5.3 定位为旗舰模型，适合编码、智能体和复杂长任务，详见[模型概览](https://docs.bigmodel.cn/cn/guide/start/model-overview)。但 Coding Plan 是面向受支持编码工具的订阅，文档明确限定了适用产品，且 Coding Plan 与普通 API 使用不同端点和密钥体系，参见[Coding Plan 概览](https://docs.bigmodel.cn/cn/coding-plan/overview)和[快速开始](https://docs.bigmodel.cn/cn/coding-plan/quick-start)。

因此，仓库中的 `glm53_dialogue` 仅是默认禁用的能力预留：

- 当前 GLM Pro/Coding Plan 用于开发 Companion Hub，而不是为 Hub 的最终用户请求提供运行时推理。
- 只有取得独立、允许服务端运行时调用的普通 API key，并确认计费和条款后，才可以启用该端点。
- 普通 API 仍通过供应商中立契约接入；兼容方式参考[GLM OpenAI SDK 调用说明](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)。

## 3. 隐私与出站规则

```text
L0/L1 ── dialogue ──> deepseek-v4-flash ──失败──> glm-5.2
      └─ utility  ──> sensenova-6.8-flash-lite ──失败──> deepseek-v4-flash
L2    ──强制改路由──> local_private
L3    ──立即阻断（零 provider 调用）
```

路由器在 provider 之前执行 `EgressGuard`。端点同时声明 `runs_local` 和 `max_privacy_level`，形成双重校验。异常只暴露稳定原因码，不把 prompt、回复或供应商错误正文写进追踪记录。

## 4. 配置发布模型

配置文件为 `config/hub.example.yaml`，包括模型端点、三条必需路由和观测参数。主要约束：

- 禁止未知字段，因此 `api_key` 等明文字段无法混入 YAML。
- 密钥只接受 `env:NAME` 引用；本地模型可以没有密钥。
- `dialogue`、`utility`、`private` 三条路由缺一不可。
- 禁用或不存在的端点不能被路由引用，`private` 不得引用云端端点。
- 新文件先解析、强校验并执行可选异步 validator，全部成功后才在锁内原子替换当前快照。
- 失败时保留 last-known-good；每次发布和回滚生成新版本及无载荷审计记录。
- watcher 遇到临时删除、非完整写入或校验错误不会退出。

运行时通过 `/api/v1/meta/config` 返回版本、内容哈希和安全模型摘要，不返回 `secret_ref`。`/healthz` 返回当前配置版本；最近一次热更新失败时服务保持可用，但状态标为 `degraded`。

## 5. 可观测性和验收

最小观测记录 `trace_id`、路由、端点、尝试次数、耗时、成功状态和异常类型。`prompt`、`content`、`message`、`token` 等字段递归脱敏。

CI 覆盖以下安全断言：

- L2 请求从不进入云 provider，L3 对所有 provider 都是零调用。
- 主端点按有限次数重试后才降级，不会无限循环。
- trace 和结构化日志不包含测试正文或异常详情。
- 坏配置、validator 失败、错误私密路由都不能替换已发布快照。
- 合法热更新可见，随后坏更新仍保留上一版；回滚生成新版本。
- OpenAI-compatible 参数、用量和成本估算通过 mock provider 验证。

真实供应商连通性不放进公共 CI，避免泄露密钥或受免费服务容量波动影响。开发机可加载 `.env.local` 后运行 `make llm-check`；脚本失败时只输出异常类型。
