5. [03-开发规划.md](./03-开发规划.md)：里程碑和阶段门槛；
6. 再根据当前任务进入专项设计。

## 2. 真源优先级

同一信息冲突时，按以下顺序判断：

1. 运行代码、Pydantic Schema、Alembic migration；
2. 标记为 Active 的专项设计；
3. Accepted ADR；
4. Current Record；
5. Phase Record / Historical；
6. Prototype。

| 位置 | 只负责什么 | 不应包含什么 |
|---|---|---|
| `README.md` | 项目入口、能力概览、启动方式 | 逐项任务、测试流水账 |
| `docs/TASKS.md` | 当前执行队列、里程碑摘要、最新质量基线 | 完整架构设计、历史实现细节 |

## 5. 当前关键真源关系

- `21～25` 是记忆历史基线；新设计以 `30/31` 为准。
- `17/19` 是聊天和 WS 历史记录；当前状态机以 `09` 为准。
- `27/28` 是 Vue 迁移记录；当前 UI 规则回写 `05/06/20`。
- `29` 是 P5 前置过程；当前使用期只看 `32`。
- `34` 负责通用工具、多终端、屏幕与传感器；`35` 只负责地图/天气垂直切片。
- `34` 定义通用设备工具与主动感知边界；`36` 是 Home Assistant 连接、实体策略、控制确认和 HA 事件映射的专项真源。
- `07` 定义形象领域模型与能力降级；`Live2D运行时接入` 只负责受许可 Cubism Web Runtime 的部署和前端适配契约。
- `37` 是 M3B 认知调度闭环真源；`TASKS` 只记录其交付状态和后续门槛。
- `34` 定义屏幕工具和多终端通用边界；`38` 专门定义周期性屏幕感知、即焚、去重与主动话题规则。
- 配置生命周期按领域区分：模型/路由保存即生效，Persona 使用草稿发布，其他高风险配置按专项设计决定。

## 6. 维护规则

1. 新功能优先补现有 Active 文档，确有独立边界时才新增文件。
2. 当前进度只改 `docs/TASKS.md`；README 和 Active 文档只保留高层状态或设计事实。
3. Phase Record 完成后冻结，只允许勘误和补充“当前真源”链接。
4. 设计被替代时，在本索引记录新旧真源，不删除历史证据。
5. 密钥、密码、精确位置、原始传感器和截图不得写入文档。
