# 分级长期记忆：交付与验收

更新：2026-11-11。设计：[记忆分级与遗忘方案](./记忆分级与遗忘方案.md)；逐包进度：[实施计划](./记忆分级实施计划.md)。本批代码尚未提交，不编造业务提交哈希。本文记录 v1 的实际行为，覆盖早期设计中尚未实现的表述。

## 已落地的行为

1. **宽进提取**：提示词要求保存明确的家庭、关系、作息、偏好等原子事实，不以重要性作为入库门槛。单条输入按4000字符、200字符重叠分块；模型返回达到12条时进一步拆分继续提取，不再总共截断到4条。前6条同会话、同等或更低隐私消息用于消歧；模型候选记录这些依赖来源，来源删除继续遵守原有围栏。规则兜底不等于模型提取完整。
2. **统一中级**：新增和旧数据迁移均为 `medium`，重要性与等级分开。旧 `access_count` 不转换成有效使用。原 pin 映射为固定等级。
3. **六级记忆**：核心、重要、中级、一般、不重要、冷存档。自动遗忘只改等级，不删除正文。冷存档仍参与全层事实精确查找；再次有效使用唤醒中级。
4. **强化**：回答明确复用1分，成功只读工具明确复用2分，用户再次支持2分，人工确认3分。同记忆同回合只计一次、取最高分；每天封顶3分。仅检索或注入不强化。30天累计6分且3个使用日，中级→重要；90天18分且8个使用日、在重要层至少14天，重要→核心。低置信度事实不自动晋级。
5. **降级**：核心180天、重要90天、中级30天、一般60天、不重要180天未使用降一级；重要性≥0.4乘2、≥0.8乘4。固定记录不自动变化。停机很久也只降一级，之后重新计时。
6. **事务与版本**：使用事件唯一键、记忆行锁、独立 lifecycle_version；操作不会改记忆语义 updated_at。手动调整带 expected_version，冲突返回409。用户范围校验沿用现有管理员/成员权限模型。真实删除清理使用和变更历史。
7. **检索**：相关性和权限先于等级；候选一部分来自热层，其余覆盖全层。事实槽精确匹配覆盖冷层，deep API取消热层预留。等级不能让无关事实绕过相关性门槛。版本为 hybrid-lifecycle-v7。
8. **后台与回执**：新后处理使用 chat-postcommit-v2 队列资源，旧worker不能领取；每次尝试持久记录消费者身份。失败按30/120/600秒重试，最多4次，仍受父预算与来源有效性约束。聊天回执显示新增/补充/冲突与实际Job状态，点击刷新查询。不会靠助手说“记住了”判断成功。
9. **管理页**：默认最新新增优先，等级筛选、逐条改级、固定/解锁、使用次数/最后使用时间、变更历史；保留已有批量删除功能。

## 接口

均使用已有 `/api/v1/admin/memories` 鉴权，不新增旁路：

| 操作 | 路径/参数 |
|---|---|
| 列表 | GET，`tier=medium`、`newest=true`，兼容原分页/过滤 |
| 手动等级 | PATCH `/{id}/lifecycle`，`tier`、`locked`、`expected_version` |
| 人工确认 | POST `/{id}/confirm`，同UTC日重复点击不重复计数 |
| 变更历史 | GET `/{id}/lifecycle-events`，最多最近100条 |
| 深度检索 | POST `/query`，原参数加 `deep: true` |

## 你新开会话的验收步骤

1. 刷新开发页面并登录，新建会话，正常讲几条新的、可核实的信息，不需要每句加“记住”。可以用合成信息先测。
2. 等助手回复后，点记忆回执旁的刷新。应看到整理完成及实际新增/补充数；若重试或失败，查看任务原因，不把空列表解释为已保存。
3. 打开记忆库按“最新”查看，新增记录应该为中级；多条事实应分别保存。具体条数依赖真实模型提取，自动测试不保证真实模型100%覆盖。
4. 再新建会话询问刚才的信息，核对跨会话召回；单次检索不会自动升为重要。
5. 管理页可把一条合成记忆设为冷存档，再精确问该事实；可召回且有效使用后回到中级。固定后应保持该等级。不要为了验收对真实资料做删除操作。
