### 3. Batch A 设计

#### 3.1 通道契约（/ws/voice）

- 鉴权：与 `/ws/chat` 相同的 `authenticate` 帧（AuthService 会话）。
- 握手 `voice.hello`：`{conversation_id, privacy_level, format: "pcm_s16le", sample_rate: 16000, channels: 1}`。Batch A 只接受 PCM16/16k/单声道；不匹配返回 `voice.format_unsupported` 后关闭。可选 `continuous: true` 声明**连续对话（电话模式）**：客户端麦克风常开、不发送 PTT 边界，服务端自动 VAD 断句即发送；播报中检测到人声即打断（barge-in）；该模式下跳过唤醒词待命门（通话中不应每句重新唤醒），且上一回合尚在 ASR/生成间隙时到达的新话语会先打断旧回合再处理，而非静默丢弃。
- 上行：
  - 二进制帧 = PCM16 音频；
  - `utterance.begin` / `utterance.end`：PTT 显式边界（与 VAD 自动断句二选一，显式优先）；
  - `interrupt`：客户端主动打断（调试/按键）。
- 下行：
  - `voice.transcript`：ASR 结果（含 `is_final`）；
  - `voice.sentence`：即将合成的一句话（`index`、`mime`）；
  - 二进制帧 = 该句的 TTS 音频分片（与最近一个 `voice.sentence` 对应）；
  - `voice.sentence.end`：一句音频结束（客户端可衔接播放）；
  - `turn.accepted/reply.committed/turn.cancelled`：复用聊天回合生命周期事件语义；
  - `voice.interrupted`：服务端检测打断，附 `interrupted_at_seq`（打断点）。
- 错误：`voice.asr_unavailable`、`voice.tts_unavailable`（L2 无本地 TTS 时，回合仍走文字）。

#### 3.2 组件与协议（server/app/voice/）

```
VoiceActivityDetector（协议） EnergyVad：audioop RMS 阈值 + hangover 尾帧
SpeechRecognizer（协议）      MiMoAsrRecognizer：WAV 包装 + base64 上云，整段转写
SpeechSynthesizer（协议）     synthesize(text, privacy) -> AsyncIterator[bytes]
                             MiMoTtsSynthesizer：pcm16 直出（24kHz），主通道
                             SenseAudioTtsSynthesizer：mp3 24kHz 分片（云端音色/克隆音色）
                             EdgeTtsSynthesizer：mp3 分片，免费兜底
TtsProviderChain              逐句选择提供方：首块成功才选定，失败冷却 60s，
                             L2 只允许 runs_local=True 的提供方
SentenceBuffer                流式 delta 按强标点切句，60 字上限强制 flush
```

- **提供方并存与故障转移**：MiMo 为主、SenseAudio 云端音色为可选中间通道、edge-tts 为兜底。逐句独立选择：主通道首块前失败或空流时无感切换备选，并进入 60 秒冷却；中途断流则该句音频跳过、回合继续（文字不丢）。`voice.sentence` 事件携带实际提供方的 `mime` / `sample_rate` / `provider`，客户端逐句自适应格式。
- **隐私**：上行语音转写按回合 `privacy_level` 走既有 ChatService 闸门（L2 强制本地 LLM）；MiMo ASR/TTS、SenseAudio TTS 与 edge-tts 均为云端——L2 音频禁止交给云端识别器（`voice.asr_unavailable: local_asr_required`），L2 回复文本禁止出站合成（提供方链只保留 `runs_local=True`，当前没有则降级纯文字并下行告知原因）。
- **配置中心化**：`HubConfig.voice` 节（`asr` 单选 + `tts` 有序链，密钥走 `secret_value`/`secret_ref` 双模式）进数据库配置中心，后台「模型与路由 → 语音」页可视化管理，`PUT /admin/config/current` 保存即生效；`ConfigVoiceSource` 每条话语解析一次提供方，管理端改配置无需重启。MiMo API Key 直接在后台填写，不落 .env.local。
- **句级切分**：LLM 流式 delta 累积，遇 `。！？!?\n` 或超过 60 字 flush；首句立即送 TTS（docs/00 §3.2 全链路流式）。
- **Markdown 清洗（`app/voice/speech_text.py`）**：回复可能是 Markdown（标题/链接/行内代码/表格/围栏代码块），直接合成会念出符号。流式分句用有状态 `MarkdownSpeechFilter`（跨句记忆围栏代码块状态，代码行整句跳过）；桌宠播报与完整回复用 `markdown_to_speech_text`（移除标题/链接保留锚文本/URL/行内代码/表格线/HTML 标签，`/` 分隔词读作"顿号"）。清洗后为空的句子安全跳过，整段为空时桌宠返回 `pet.audio.failed: tts_empty_text`、语音回合静默完成。
- **打断**：回合进行中持续接收上行音频；单帧人声能量（无 hangover 的高灵敏判定）→ `ChatService.cancel_turn(generation_id)` + 中止 TTS 任务 + 发 `voice.interrupted`。
- **降级**：当前配置没有可解析的 ASR → `voice.asr_unavailable: not_configured`；TTS 链为空或没有可用 provider → 降级文字。若配置了 edge-tts，可作为 L0/L1 兜底；L2 只允许 `runs_local=True` 的本地 TTS。LLM 路由耗尽 → 沿用聊天 WS 的 `turn.failed` 语义。

#### 3.3 MiMo 接入要点

- ASR（`mimo-v2.5-asr`）：OpenAI 兼容 `https://api.xiaomimimo.com/v1/chat/completions`，`input_audio.data` 仅收 wav/mp3 base64（≤10MB）——服务端把 PCM16/16k 包 WAV 头再上传；语言由 `HubConfig.voice.asr.language` 提供（默认 auto）。
- TTS（`mimo-v2.5-tts`）：`messages` 的 assistant 内容为待合成文本，`audio={"format":"pcm16","voice":"冰糖"}`，SSE 流式返回 `delta.audio.data`（base64 PCM16 24kHz 单声道）；音色由 `HubConfig.voice.tts[*].voice` 提供，预置：冰糖/茉莉（中文女）、苏打/白桦（中文男）、Mia/Chloe/Milo/Dean（英文）。
- 计费：TTS 限时免费，ASR ¥0.5/小时。

#### 3.4 依赖

新增运行时依赖 `edge-tts`（纯 asyncio）与 `httpx`（原为 litellm 传递依赖，转正显式声明）。faster-whisper/silero-vad/onnxruntime 留到 Batch B 作 L2 本地路径按需引入。

当前 `EnergyVad` 使用 Python 标准库 `audioop`，本轮 pytest 已出现“Python 3.13 将移除 audioop”的弃用警告，因此 Batch B 的 silero-vad 替换同时属于兼容性收口，不只是识别质量优化。

#### 3.5 SenseAudio 接入要点（2026-09-15）

SenseAudio（商汤开放平台）作为第三类 TTS 提供方接入，定位是「云端系统/克隆/生成音色」，仍排在故障转移链内使用；L2 私密内容禁止出站（`SenseAudioTtsSynthesizer` 声明 `runs_local=False`，由链降级）。

**连接与配置分层**：

- 共享连接 `voice.senseaudio`（`base_url` 默认 `https://api.senseaudio.cn`、`secret_value`/`secret_ref` 双模式、`tts_model` 默认 `sensenova-tts-2.0`、`enabled` 开关）服务管理端「声音管理」代理与 TTS 条目兜底；Admin 配置 GET 脱敏、保存按掩码还原，与 MCP/push 密钥同规则。
- TTS 链条目 `provider="senseaudio"` 可留空 `base_url`/密钥，回退到共享连接，`voice` 字段指定音色 ID（默认 `male_0018_a`）；条目自带密钥优先。两者都没有密钥时配置校验直接拒绝，`build_voice_providers` 对无法解析密钥/地址的条目跳过并告警。
- 聊天管线输出 mp3（24kHz 单声道，t2a_v2 非流式整段合成后按 4 KiB 块切片），`mime=audio/mpeg` 与 edge-tts 通道一致；按字符计费，句级切分仍由管线 `first_tts_chunk_chars` 负责。

**Admin「声音管理」模块**（`/api/v1/admin/senseaudio/*`，全部经 Hub 代理、密钥只存配置中心）：

| 接口 | 用途 |
|---|---|
| `GET/PUT /status` `/connection` | 连接状态与保存（保存即发布热生效；启用前必须有可解析 Key） |
| `GET /voices` | 音色目录（system/voice_clone/voice_generation/all），标注 `free_tier` |
| `POST /preview` | 试听合成（≤500 字、≤2MB 音频、speed/vol/pitch/format 可调） |
| `GET /asr/records` | 识别历史分页（按 `session_id` 可选过滤） |
| `POST /clone/upload` + `POST /clone` | 上传参考音频（MP3/AAC/WAV、≤50MB、3–30 秒清晰人声）并克隆音色，`label` 即生成后的 voice_id |

- Free（普通音色）套餐当前可合成系统音色为 `child_0001_a/b`、`male_0004_a`、`male_0018_a`（`FREE_TIER_VOICE_IDS` 静态维护）；上游"no access to the specified voice"映射为套餐引导话术（HTTP 403），音色库页可按「Free 可用」筛选。
- 模型工作区的 TTS 链新增「+ SenseAudio」条目；音色下拉动态加载目录（只列克隆/生成音色 + Free 系统音色），未启用时保留静态 Free 选项。克隆/文生音色共享套餐生成额度（Free 每期 2 次），超出按次计费。
- 回归覆盖：连接往返脱敏、启用强制 Key、未启用拦截目录、试听/识别历史、上游错误映射、克隆上传格式与 label 白名单、套餐引导与 Free 标注推导（`tests/test_senseaudio_admin.py` 10 例 + `test_voice_config.py` 扩展）。

### 6. M2 真机延迟诊断（2026-08-21）

`make llm-first-token-bench` 使用与语音窗口相近的 8 条短上下文，直接流式请求运行配置中的 dialogue 端点，不创建会话/消息，不输出密钥。首轮结果：

| 端点 | 首 token | 总耗时 | 结果 |
|---|---:|---:|---|
| `sensenova_deepseek-v4-flash` | 1.623s | 1.635s | 成功 |
| `sensenova_6.8-flash-lite` | — | 20s | 超时 |
| `glm-4.7-flash` | — | 0.226s | RateLimit |
| `glm-5.3` | — | 0.196s | RateLimit |
| `sensenova_glm-5.2` | — | 0.189s | RateLimit |

结论：当前可用组合的理想分段下限约为 0.832s ASR + 1.623s LLM + 0.846s TTS = 3.301s，已高于 1.8s 验收线。不应通过放宽统计口径“达标”；要保留原指标，需同时改为增量/流式 ASR 和独立的低延迟语音 LLM 路由。

#### 6.1 语音专用 LLM 路由（2026-08-28）

配置中心现支持可选 `routes.voice`。L1 语音回合发起时标记为 `voice`，路由存在则使用其 primary/fallback/超时策略，不存在则由 Router 回退到 `dialogue`，因此旧配置无需迁移。文字回合不受影响；L2 无论请求何种路由都继续强制使用本地 `private`。

语音 route 可以选择首 token 更快的模型。若该 route 没有任何支持 Function Calling 的端点，ChatService 会为该语音回合停挂查询与设备工具，保留普通对话能力，避免工具 schema 令低延迟端点整条失败。需要语音中调用天气、屏幕或 Home Assistant 时，应至少把一个支持工具调用的模型放入 voice primary/fallback。

`make llm-first-token-bench` 对已发布配置优先评测 `voice`，未配置时仍评测 `dialogue`，报告显式包含实际 route。端点选择与 20+20 真人判卷仍以真实测量为准，不因代码路由接通而宣称 M2 达标。

自动判卷同时要求完成回合、非空首音频和打断样本各自达到 20。完成了回复但没有配置 TTS、TTS 失败或未真正产出音频的回合，只增加完成回合数，不能再用于满足首音频样本门槛；`overall_pass` 仅在三类样本量和两项 P90 指标全部通过时为真。

#### 6.2 ASR 预取与首段 TTS（2026-08-28）

在不引入新 ASR 服务的前提下，自动 VAD 检测到说话后的首个静音帧时，Hub 会用截至该帧的完整音频启动一次 ASR 预取。能量 VAD/Silero 原本仍需约 450ms hangover 才确认话语结束，因此识别可以与这段等待重叠。若 hangover 内恢复说话，预取任务与结果立即作废；话语最终结束时，仅当识别器实例仍与当前热配置一致才复用结果，否则执行原来的完整转写。L2 仍禁止云端识别器接收音频。该方案不是持续输出 partial transcript 的真流式 ASR，但在保留现有提供方与最终文本语义的前提下，先消除一段可确定重叠的等待。

`voice.transcript` 增加 `asr_prefetched`，延迟滑窗增加 `asr_prefetched_count`，用于真人判卷时确认优化是否命中。LLM 首回复若迟迟没有句号等强标点，`SentenceBuffer` 会优先在软标点或 `voice.first_tts_chunk_chars`（默认 24，允许 8～60）切出首段送入 TTS；完成首次播报后仍恢复强标点与 60 字上限策略，避免整篇回复被切成过多碎片。

#### 6.3 连续对话抗噪与幻听防线（2026-09-16，2026-09-18 加固）

电话模式麦克风常开后，环境噪声不再被「按下才录」天然挡住，五层防线收敛噪声与 Whisper 幻听：

- **断句层（Silero 概率 VAD）**：运行环境补装 `silero-vad` + `torch`（macOS arm64 CPU wheel）后 `create_default_vad` 自动升级为 Silero——只有真实语音概率过阈才触发断句，风扇/电视等稳态噪声不再产生"话语"。路由新增 `vad_factory` 注入点（测试用能量 VAD 保持确定性），`voice.hello` 即后台预热 torch/ONNX（`SileroVad.warmup`），初始化成本不落在第一句话上；预热失败仍走首次喂帧降级能量 VAD。
- **ASR 层**：faster-whisper 改为 `vad_filter=True`（无语音段直接剪掉，纯噪声片段转写为空 → 回合静默跳过）+ `condition_on_previous_text=False`（阻断幻觉跨窗滚雪球/复读循环）。
- **ASR 逐段复核**：`no_speech_prob>0.5 且 avg_logprob<-0.9` 的低置信段、`compression_ratio>2.5` 的复读段（≥8 字）整段丢弃。
- **提示词回显检测**：噪声上 whisper 倾向把 `initial_prompt` "念"出来（实测症状："这段与智能伴侣小艾（Aria）的普通话对话"）。转写与提示词做字块重合双重校验（overlap≥0.5 且 prompt coverage≥0.55）判幻听丢弃；真实话语即使提到"智能伴侣小艾"只会命中零碎片段，不受影响。
- **断句/回合层**：自动断句话语 600ms 总长下限（含 450ms hangover，单次噪声脉冲直接丢弃；PTT 仍 150ms）；连续模式 6 秒内逐字相同转写只处理第一次（回声/复读形态）。文字输入与卫星设备通道不受影响。
