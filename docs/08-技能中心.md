# Skill 中心：动态能力与学习方案

> 2026-09-28。本文定义目标架构与分期实现。Skill 是可移植的任务说明；实际权限始终由 Hub 的连接、工具、Action Registry 和隐私策略决定。

当前实现：S1 的 ZIP/创建/持久化/启停与 S2 的只读 GET 聊天链路已接通（PNKX 技能也统一走 Admin 配置的通用连接，见第 2 节）。说明型 Skill 的文本按相关性限量加入任务参考；上传后可在停用状态补充声明式 API 契约。修改生成不可变版本，可停用后回滚；Admin 可预览匹配结果。智能创建可从粘贴文本或 MD/TXT/JSON/YAML/HTML/DOCX 文档，经私密模型路由生成待审核草稿；服务端校验格式和 API 路径来源，保存后默认停用。S2 的通用 HTTPS 只读连接是唯一执行链路：Admin 配置固定服务地址、认证方式（含登录获取 Bearer）和精确路径白名单，启用后可按相关性挂载 GET 工具；执行时复查状态，运行元数据写入 `skill_run`。同一版本和操作在最近 10 次运行中出现至少 3 次相同的可处理错误时，系统会自动生成一条带运行证据的排查建议，供 Admin 查看或忽略。

对话内主动沉淀草稿（第 5 节的首个落地切片）已接通：聊天挂载 `propose_skill` 工具，用户粘贴接口文档或给出链接时（链接由服务端复用只读网页抓取工具取正文，L2 私密会话拒绝外发），生成器强制 evidence/path/auth 逐字出自原文后写入 `skill_draft`（迁移 0052）；回合提交后另有正则闸门 + 私密路由提取的被动收割，提取结果非逐字出自用户消息即拒绝。草稿在 Admin「待审草稿」页审阅：通过即创建停用技能（与现有技能重名则阻断审批），忽略后同内容再现会重新进入待审；草稿永不直接执行。

修订候选与审阅前试跑（第 10 节的第二个切片，迁移 0053）已接通：用户在对话里纠正某个已有技能的用法或接口时，`propose_skill` 传 `target_skill` 生成该技能的修订草稿（记录起草时的版本基线，且不允许悄悄切换连接）；审批通过后为该技能创建新的不可变版本（名称沿用、内容以草稿为准，仍保持停用），期间技能被改动或仍处于启用状态则阻断审批，可照常回滚旧版本。草稿列表支持「试跑」：对草稿声明的第一个无需必填 path 参数的只读操作，走与运行时完全相同的连接白名单与认证闸门做一次真实 GET，只记录通过/原因码不落响应内容，供 Admin 审阅前参考（非通过硬门槛），修订草稿展开时展示与目标技能当前版本的差异摘要（描述/说明/操作增删改）。

S3 写闭环已接通（第 9 节能力层的首个写链路，迁移 0054/0055）：已启用技能的 `confirm` 风险操作经 `sync_skill_actions` 同步为 Action Registry 的 A2 动作（`skill.<技能名>.<操作名>`，每次确认、L1 上限、回执验证），技能启停/改版/审批后自动重同步。写动作只经计划—确认—执行链触发：泛型执行器 `skill_write` 不作为聊天工具挂载，执行时按数据库实时状态复核技能/操作/连接并重新校验参数，绝不信任计划里缓存的旧契约。连接新增独立的写入路径白名单（`allowed_write_paths`，默认空，最小权限）；`SkillHttpClient.skill_write` 校验方法非 GET、透传计划步骤幂等键为 `Idempotency-Key` 头，401 自动重登。执行证据写入 `skill_run`，验证回执只含技能名/操作/状态，不含远端响应正文。导入技能时持久化 SKILL.md 原文（迁移 0055），技能详情可查看，作为来源与审计参照；ZIP 包内其余附件仍不保存。样例回放与受控自动晋级仍按下文路线实施。

## 1. 产品目标与边界

用户可以上传 ZIP、在 Admin 中手工创建 Skill，或让 Aria 根据任务记录生成候选 Skill。已发布 Skill 在相关对话中自动匹配，按需加载说明和工具。用户可以查看来源、依赖、权限、调用记录、版本、测试结果，并停用或回滚。

Skill 可增加知识、流程和对已授权 API 的使用方式，但不能凭文字获得文件、网络、设备或账号权限。当前导入包中的 `scripts/` 不保存、不执行；后续附件存储阶段再纳入受控保存。外部 Skill 文本视为不可信内容；不允许覆盖系统提示、权限策略或用户确认要求。

## 2. 包格式

兼容 Agent Skills：根目录或单个顶层目录内必须有 `SKILL.md`，YAML frontmatter 至少包含 `name` 和 `description`；可包含 `references/`、`assets/`、`scripts/`。Aria 扩展文件 `aria-api.yaml` 是可选的声明式 HTTP 契约。没有该文件的包是说明型 Skill，可以指导使用现有工具；不会自动获得 HTTP 调用能力。

`aria-api.yaml` 允许声明英文小写连接标识；所有连接一律由管理员在「API 连接」页配置，`pnkx` 是保留 ID，技能契约不得使用（历史上的 PNKX 生活服务直连适配器已于 2026-09-28 移除，技能不再借用 `X-Integration-Token` 特权链路）。操作含 `name`、`description`、`method`、`path`、`risk` 和扁平参数。可选 `auth` 只描述用户名密码登录获取 Bearer 的路径、请求字段及响应令牌字段，不携带凭据。相对路径必须固定，以 `/` 开头；不能包含 URL、变量主机、查询模板或路径遍历。连接地址与凭据由服务端配置提供，绝不从 Skill 包读取。参数均经 Pydantic 模型校验；模板变量只可来自已声明参数。响应裁剪后返回模型。

智能创建流程：Admin「技能中心 → 智能创建」填写系统标识，粘贴文档或上传文件；`POST /api/v1/admin/skills/generate` 或 `/generate-upload` 优先从明确的 Markdown 方法/路径表或接口标题直接提取契约，避免大文档一次性模型输出被截断。没有明确接口结构时才使用私密模型路由。服务端先对常见令牌形态脱敏，限制文档长度，校验生成 JSON 和路径在原文中出现；模型输出截断会显示明确错误。页面展示进度、错误、警告、文档依据和可编辑契约；人工核对后调用 `POST /api/v1/admin/skills/generated` 保存为停用版本。新系统标识可保存契约，但在配置并启用对应连接前不会变成 API 工具。当前 DOCX 读取正文文字；PDF、扫描件和多文件知识库尚不支持。

PNKX 情侣卡券文档的认证是 `Authorization: Bearer`，现有 PNKX 生活连接使用 `X-Integration-Token`。因此从该文档生成的契约使用独立 `pnkx-admin` 连接标识；管理员需要配置正确的 HTTPS 地址、登录路径与业务路径白名单，不能直接复用 PNKX 生活连接。文档中的 Excel 导出 GET 不适合当前 JSON 只读工具，会被排除；POST/PUT/DELETE 业务操作只登记，不进入执行链。

PNKX 源码已有匿名 `POST /clientLogin`，请求体使用 `userName`、`password`，成功响应的顶层字段为 `token`，因此无需增加公开发令牌接口。Skill 的 `api.auth` 声明 `type: login_bearer`、登录路径 `/clientLogin`、用户名/密码字段和令牌字段；不包含账号或密码值。此部署的卡券服务地址为 `https://admin.pnkx.top:8/prod-api`，其中 `/prod-api` 是固定网关前缀；操作路径仍填写 `/px/card/getCardByUserId`。管理员在 `pnkx-admin` 连接中审批 `/clientLogin` 登录路径及只读业务路径。账号密码通过技能详情页提交，使用独立主密钥加密后按 Skill ID 存在 `skill_credential` 表；API 只返回配置状态与更新时间，不回显明文。运行时按需登录、缓存令牌，业务请求遇到 401 时重新登录一次。移除凭据后已挂载的工具也会在执行时被拒绝。

示例包在 [`docs/examples/pnkx-lovers-card/`](examples/pnkx-lovers-card/)；部署时先运行 `alembic upgrade head` 到 `0051_skill_credentials`。2026-09-28 依据 pnkx-admin 源码梳理批量导入了 14 个生活服务技能（`docs/examples/pnkx-*`，生成器 `scripts/gen_pnkx_skills.py`、导入器 `scripts/import_pnkx_skills.py`），按域挂到 3 个新增的 `login_bearer` 连接：`pnkx-life`（待办/订阅/日历/提醒/纪念日/经期/笔记/日记/记账）、`pnkx-food`（菜谱/餐饮计划/购物/书架）、`pnkx-media`（壁纸/博客内容），单连接白名单受 50 条上限约束。全部技能以停用草稿入库，逐个在详情页配置登录凭据并核对后即可启用。连接的认证方式选“用户名密码登录获取 Bearer”，登录白名单填 `/clientLogin`，业务白名单至少填 `/px/card/getCardByUserId`。然后在「技能库 → pnkx-lovers-card → 此技能的登录账号」输入账号密码并加密保存，最后启用连接，在 L1 对话中查询。账号应是专用于助手的最小权限账号；当前 PNKX 卡券接口只要求已登录，实际数据由登录用户身份决定。

数据库密文依赖 `ARIA_SKILL_CREDENTIAL_KEY`（Fernet 密钥）。本地运行或 Docker Compose 部署时把该主密钥配置在服务端环境中并重启 Hub；它不能与数据库备份存放在一起，也不能丢失，否则已保存的凭据无法解密。密钥可用 `python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'` 生成。不要把账号、密码或主密钥写进 `SKILL.md`、`aria-api.yaml` 或提交到 Git。旧的环境变量账号密码引用仍可作为回退方式，但本部署已移除 `pnkx-admin` 的这两个引用，改用技能关联凭据。

通用只读连接流程：Admin「技能中心 → API 连接」配置与 `api.connection` 相同的标识、HTTPS 服务地址（可含固定路径前缀）、认证方式（无认证、固定 Bearer、用户名密码登录获取 Bearer 或 `X-` 自定义头）、`env:NAME` 密钥引用和逐条精确匹配的路径模板。连接与 Skill 都启用后，L1 对话才会按相关性挂载 GET 操作。执行前重新读取两者；停用连接或移除白名单即时阻断已选中的工具。拒绝重定向，响应上限 64 KiB，模型可见内容上限 4000 字。`GET /api/v1/admin/skills/{id}/runs` 返回脱敏运行记录，不含请求参数、令牌或响应。固定令牌连接仍需在服务端配置密钥环境变量；用户名密码登录可使用按 Skill 加密保存的凭据。此阶段尚未提供连接健康检查或基于实际返回结构的契约测试。

基础学习建议：执行失败会留下不含参数和响应的 `skill_run`；同一技能版本、操作和错误码在最近 10 次运行中出现 3 次后，支持的错误码会产生唯一 `skill_suggestion`。目前建议只覆盖认证、路径、参数、连接和响应格式的排查，不生成未经证实的 API 路径或修改现有技能。Admin「学习建议」可查看证据次数并忽略；`GET /api/v1/admin/skills/suggestions` 返回待审核项。它是运行反馈闭环的第一步，不能等同于从用户纠正中自主习得新能力。

部署顺序：先备份并执行 `alembic upgrade head`，确认至少到 `0051_skill_credentials`，再开放技能中心管理页。若运行库仍缺少 `skill` 表，列表、创建和导入接口返回 `503 skill_schema_not_migrated`，提示管理员迁移；不能把生成成功误认为保存成功。

示例：

```yaml
schema_version: 1
connection: pnkx-admin
operations:
  - name: coupon_list
    description: 查询情侣卡券
    method: GET
    path: /coupon/list
    risk: read
    parameters:
      status: {type: string, required: false, location: query}
  - name: coupon_redeem
    description: 核销指定情侣卡券
    method: POST
    path: /coupon/{coupon_id}/redeem
    risk: confirm
    parameters:
      coupon_id: {type: integer, required: true, location: path}
```

上述路径是格式示例，真实 PNKX 路径必须从实际 API 文档和联调结果取得。模型从 API 文档提出契约草稿时，系统展示原文与生成结果的差异，不把模型猜测视作已验证接口。

## 3. 状态与版本

`draft → validated → enabled → disabled/archived`。导入或创建先生成草稿；静态校验、依赖检查和模拟调用后才可发布。更新产生不可变版本；发布指针原子切换，运行中的回合固定版本，失败可回滚。记录 SHA-256、来源、安装时间、发布人和最近测试结果。停用即时阻止新回合挂载与执行，执行前再次检查状态。

文件元数据与版本存 PostgreSQL，较大的附件进入现有对象存储。查询使用已发布版本索引，Admin 编辑草稿不影响运行版本。上传限制：总压缩大小、解压后大小、文件数、单文件大小；拒绝绝对路径、`..`、符号链接、加密 ZIP、嵌套压缩包和重复文件名。只解析允许的文本格式，不执行上传脚本。

## 4. 运行链

1. 对话接入后，以用户文本对启用 Skill 的名称、描述、触发词做本地检索，每轮最多选 2 个。
2. 对每个候选检查连接在线、授权、隐私等级和所需工具；只把匹配 Skill 的精简说明加入本轮上下文，不全量注入目录。
3. 只读 HTTP 操作包装为 `ToolHandler`，复用 `ToolExecutor` 的参数和外发检查；执行时按连接 ID 重新读取 Admin 配置的服务地址、认证与白名单。返回文本截断并结构化。
4. 写操作包装为 `ActionDefinition`，走 `ActionPlanService → 用户确认 → ToolActionRunner`。导入 Skill 不得降低风险级别；外部写操作默认 A2 每次确认，必须有幂等键和回执。高风险或不能验证的接口保持不可执行。
5. 运行日志记录 Skill/版本/操作、时间、状态、耗时、脱敏错误码和确认链 ID，不存令牌与完整隐私数据。

PNKX 生活数据的聊天读取由技能中心的 `pnkx-life` 等连接提供；旧的集成令牌生活工具不再注册到生产聊天。旧管理页 `/admin/integrations?tab=pnkx` 跳转到技能中心的 API 连接页。集成令牌配置仍供 PNKX 待办镜像同步与旧 API 使用，不能随页面一并删除。Skill 操作命名空间为 `skill.<skill_name>.<operation>`，避免与内置工具冲突。

## 5. 自主学习

候选来源：用户明确说“记住这种做法”、同类任务多次成功、用户纠正了参数或步骤、一次失败后成功重试。学习器只抽取最小必要的任务模式、前置条件、步骤和测试例，不把对话隐私原文写进公开包。候选保留来源证据和隐私级别。

生成流程：事件聚合 → 去重与归因 → 生成 Skill 草稿 → 静态校验 → 历史样例回放与模拟测试 → 与当前版本比较 → Admin 审阅发布。系统可以自动修订草稿，不自动扩权或发布写操作。评价指标包括匹配准确率、任务成功率、无关触发率、工具错误率、确认取消率和平均 token 开销。

## 6. Admin 页面

入口为“能力接入 → 技能中心”。提供：技能库（搜索/筛选/启停/版本）、导入（ZIP 与解析报告）、创建（表单和源文件编辑）、详情（说明/文件/依赖/权限/操作契约）、测试台（给定输入展示匹配、计划、模拟与真实只读试跑）、学习建议（证据、差异、采纳/忽略）、运行记录。错误需可操作，例如“PNKX 未配置”“路径参数缺失”“接口响应不符合契约”。

## 7. API 与数据

Admin API：`GET /api/v1/admin/skills`、`POST /api/v1/admin/skills/import`、`POST /api/v1/admin/skills`、`GET /{id}`、`POST /{id}/validate`、`POST /{id}/publish`、`POST /{id}/disable`、`GET /{id}/versions`、`POST /{id}/test`、`GET /suggestions`。所有管理写接口要求 Admin 鉴权与审计。数据库至少包括 `skill`、`skill_version`、`skill_run`、`skill_suggestion` 四类记录；版本内容不可变。

## 8. 交付顺序与验收

| 阶段 | 交付 | 验收 |
|---|---|---|
| S1 基础 | 包解析、持久化、Admin 库/导入/创建/启停 | 恶意 ZIP 被拒；重启仍可见；停用后不可选 |
| S2 只读闭环 | PNKX 声明式 GET、匹配、聊天工具挂载、执行记录 | 上传卡券查询 Skill 后，对话能真实读取；无关对话不挂载 |
| S3 写闭环 | 声明式写操作、A2 确认、幂等、回执、回滚 | 未确认零写入；重复回合不重复核销；停用即时生效 |
| S4 自主学习 | 候选生成、样例回放、版本比较、审核发布 | 从用户纠正形成候选；错误候选不会进入正式目录 |

每阶段要求定向后端测试、Admin 类型检查与构建、真实 PNKX 测试环境联调。未取得真实卡券 API 契约前，只能以本地假服务验证格式与执行链，不宣称卡券功能已接通。

## 9. 让 Skill 真正扩展能力的运行时升级

历史上 `connection: pnkx` 直连生活服务适配器曾是唯一连接，现已统一为管理员配置的通用连接；自由扩展需要把三层分开：

1. **连接层**：管理员登记连接 ID、固定服务地址、认证方式、密钥引用、允许路径与隐私上限；密钥只在服务端解析。先复用现有 PNKX、MCP 和设备连接，再增加受控 HTTP 连接。Skill 包不能自行指定地址或带入密钥。连接健康检查、撤销和热更新必须在 Admin 可见。
2. **能力层**：Skill 声明输入 schema、只读/写入、路径/工具映射、输出 schema 和错误映射。安装时编译为 Hub 工具或 Action Registry 动作。只读可按相关性挂载；写入必须经过计划、确认、幂等和结果验证。Python/JS 脚本只能在独立沙箱中以声明的资源、文件和网络权限执行，不能以 Hub 主进程权限运行。
3. **任务层**：`SKILL.md` 负责何时使用、步骤和异常处理，支持引用包内资源。每轮仅加载匹配 Skill，工具可用性以实时连接和授权为准。模型提出调用，服务端校验并执行，不能让提示词代替权限。

安装过程要给出明确的兼容报告：哪些步骤只是说明、哪些 API 已转成工具、哪些因缺连接/参数/脚本运行环境而不可执行。用户上传只有自然语言 API 文档的 Skill 时，模型可以提出 `aria-api.yaml` 草稿，但必须经结构校验、模拟服务测试和管理员核对真实接口后才发布。

## 10. 自主学习闭环与晋级规则

真正的学习需要有**可验证的经验**，不能把对话摘要直接当新能力。系统记录每次 Skill/工具使用的版本、任务意图摘要、输入字段名、结果状态、错误码、用户纠正及确认结果；敏感参数值和原始响应不进入学习台账。学习器从下列证据生成候选：

- 同类请求多次成功且步骤稳定：提出新的流程型 Skill；
- 同一 Skill 反复因参数或接口错误失败，用户纠正后成功：提出新版本和差异；
- 用户明确要求“以后按这个方法做”：生成待审核草稿；
- 连接目录新增工具：提出可用的能力组合，而不是直接赋权。

候选状态为 `observed → drafted → replay_passed → review_required → published/rejected`。先用历史样例做离线回放和安全检查，再在测试环境验证工具契约。自动晋级只适用于无副作用、权限不扩张且评测达到阈值的说明型改进；新连接、脚本或写动作一律由管理员发布。发布后按版本持续观测成功率和误触发率，异常自动停用新版本并恢复上一个通过验证的版本。

实施上先落 `skill_run` 与 `skill_suggestion` 两类证据表、Admin 运行记录与候选页；再接事件聚合和模型起草器；最后做回放评测与受控自动晋级。没有运行证据和回放结果时，界面必须标为“建议草稿”，不能显示为“已学会”。
