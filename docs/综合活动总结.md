# 综合活动总结（SUMMARY-01）

## 已实现的行为

- 服务随 Hub 启动，每 60 秒检查活跃用户；首次检查延迟 60 秒。默认时区 Asia/Shanghai，复用 `ARIA_DEFAULT_TIMEZONE`。
- 日报覆盖最近一个已结束的自然日；周报覆盖最近一个已结束的周一到周日。窗口为左闭右开，SQL 查询统一 UTC；周报直接读取原始事实，不依赖日报是否存在。
- 唯一键 `(user_id, kind, period_start)` 防重复；保存后不自动覆盖。重启会补最近一天及最近一周，不批量补齐更早缺口。无需通知通道，不自动发送消息。
- 聊天读取时间线 message 摘要；浏览和屏幕读取对应事件。任务覆盖期间新建或完成的项目，状态为生成时状态。日程覆盖与期间重叠的有效安排，不推断是否实际参加。
- 首版为确定性事实摘录，未调用模型进行主题归纳。五区块各取最早 100 条，超限明确标注；单条最多 400 字，保留来源 ID。无记录不等于没有活动。
- 时间线和任务仅使用当前用户 L0/L1 数据；日程使用现有用户级日程（该表无独立隐私等级）。报告是独立持久化快照，不写入 Persona 或长期记忆。

## 存储和接口

迁移 `0071_activity_summary` 创建 `activity_summary`；用户删除随外键级联清除。有报告数据时拒绝降级删表。

全部接口沿用 ChatSessionGuard，仅访问当前登录用户：

- `GET /api/v1/activity-summaries?kind=daily&limit=30&offset=0`：历史分页，kind 可省略或 weekly，limit 1～100。
- `POST /api/v1/activity-summaries/generate?kind=weekly`：幂等生成最近完整周期，默认 daily。
- `DELETE /api/v1/activity-summaries/{id}`：删除自己的报告。

当前周期归档被删除后，下次调度会根据仍存在的来源再次生成。源记录删除不自动删除独立报告，需另行删除报告；不将报告当作原始来源恢复数据。完整源删除血缘/禁止重生成策略后续纳入 B-02/B-03。
