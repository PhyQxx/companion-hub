## 接口与实现约束

- ContextReference语义版本不能受使用统计/等级变更影响；等级使用独立lifecycle_version。
- MemoryLifecyclePolicy输入：当前tier/锁定/importance、各时间、30/90天分数和活跃天数、事实资格、当前UTC时间；输出：目标tier/原因/next_decay。纯函数不读库、不调用模型。
- 仓储提供 owned get、append_usage_once、transition_if_version、due_page。事件和变更同事务，返回已提交DTO；跨域通过端口装配，不新增直接ORM依赖。
- Usage幂等以owner+memory+turn/run+事件来源构造；同回合分数取max而非sum；日聚合再封顶3。窗口以明确用户时区日边界计算，修改时区不追溯重写历史日桶。
- 迁移先扩展后启用；旧数据中级/迁移日起保鲜，旧access_count不转换为使用；迁移前后逐用户行数、status、来源数量应一致。
- v1 本地开发默认启用新检索（生产启用前仍需真实验收），支持切回旧评分，使用collect_usage、tiered_retrieval、auto_promotion、auto_decay分开开关，关闭功能不抹除数据。
- 一般/不重要/冷存档有效使用唤醒中级；事实纠正走原有来源和冲突流程，不用升级替代真实性判定。
- 手动等级请求携expected_version，冲突409；跨用户404，固定/解锁写审计。API路径以实际路由实现为准。

## 范围调整（保留原 ID）

- 02A：本轮以整消息持久任务+幂等重试保证不虚报完成；未实现每块独立 checkpoint。超过预算会进入可见失败，不能声称后台无限续提。
- 03A：直接从有唯一键的 usage 事件按日聚合并封顶3，避免多维护一份 daily 表；语义相同，长历史量级需再验证查询成本。
- 03B：明确回答全文复用与成功只读工具参数复用才归因；同义改写和写操作的可靠来源归因仍待增强，宁可少计，检索曝光从不计强化。
- 04B：关闭 tiered_retrieval 可离线对照；没有生产影子队列、标注集或真实模型召回率结论。
- 05B：到期时间持久化、每60秒有界扫描、行锁内重算，复用 ChatService 生命周期；不额外保存无变化的 Job 步骤。晋降级仍逐条写事件。
- 06B：百万 SQLite 全层词匹配约2.43秒，尚不满足低延迟扩容目标；PostgreSQL ANN容量、真实模型质量、用户新会话验收单列待办。
