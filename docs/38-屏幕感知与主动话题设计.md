# 38 - 屏幕感知与主动话题设计

> 状态：v1 已实现（2026-08-27）
> 相关：[34-大模型工具使用与主动感知设计](./34-大模型工具使用与主动感知设计.md)、[36-Home Assistant集成设计](./36-Home%20Assistant集成设计.md)、[37-M3B认知调度闭环设计](./37-M3B认知调度闭环设计.md)

## 1. 功能定位

中枢按配置间隔周期性截取用户桌面设备（Aria Desktop）的各显示器画面，做感知哈希变化检测后交给视觉模型生成结构化摘要：

- **全量沉淀**：每份摘要写入 Timeline（`screen.observed` 事件），可检索"我下午看了什么"；
- **显著升级**：视觉模型判定 `memory_worthy` 的观察进入长期记忆（情景记忆、低重要度、自动去重）；
- **主动话题**：判定 `notable` 的观察构造 `SemanticEvent(kind="screen.observed")` 进入感知管线，经 M3B 认知循环判定后由 ProactiveDeliveryService 投递到 Web 私聊/桌面通知/语音。

本功能是用户对 TASKS「暂缓：持续后台屏幕监控」的**显式推翻**：授权模型采用纯配置开关（Hub 侧 `screen_awareness.enabled`），设备端不再逐次点击授权，但保留三道硬闸门。

## 2. 数据流

```
ScreenAwarenessLoop (tick, 默认 60s, 15~600s 可配)
  ├─ 读 config.screen_awareness（每 tick 重读，支持热更新）
  ├─ DeviceTargetResolver.resolve(capability="screen.monitor")
  ├─ 每显示器：
  │    gateway.issue(command="screen.monitor", args={target, display_index})
  │    → Desktop(TS) 不消费单次授权，Rust 端仍检查 TCC/锁屏
  │    → 资产 consume-on-read（原图即焚）
  │    → 感知哈希（Pillow 8x8 均值哈希）与上次比较，汉明距离 ≤ 阈值则跳过
  │    → analyze_vision（GLM-4v-flash @ L1）→ JSON {summary, notable, memory_worthy, topic}
  │    → TimelineStore.index_screen_observation（source_type=device, event_type=screen.observed）
  │    → memory_worthy → MemoryCandidate(EPISODIC, SYSTEM_EVENT, screen-v1) → MemoryIngester
  │    └→ notable → SemanticEvent(dedupe_key="screen:{hash}", evidence_ids=[timeline id])
  │         → PerceptionPipeline.submit(stable_for_seconds=10, handler=ProactiveDeliveryService.deliver)
  └─ 连续 3 次失败 → 该显示器冷却 10 分钟（不存在的显示器不空转）
```

## 3. 隐私与安全边界

1. **原图即焚**：截图走 `EphemeralDeviceAssetStore`（2 分钟 TTL、consume-on-read、进程内存），分析后即消失；持久化的只有文本摘要。
2. **设备端三闸门**：TCC 屏幕录制授权；锁屏时 `screencapture` 前直接拒绝（`screen_locked`）；Desktop「隐私暂停」开关断开设备连接即全线停止。
3. **Hub 侧总开关**：`screen_awareness.enabled=false`（默认）时循环空转不发任何命令；Admin 状态页可见循环健康与各屏状态。
4. **能力交集**：Desktop 在 TCC 已授权且未锁屏且未暂停时声明 `screen.monitor`，还需 Admin 在设备设置里授权 `screen.monitor` 才进入有效能力。
5. **主动输出复用全局门禁**：`screen.observed` 不在 CRITICAL_EVENTS，受安静时段/每日预算约束；反馈降频按 trigger_kind 生效——用户忽略几次后自动安静。
6. **视觉分析固定走 L1**（云端 GLM-4v-flash）；L2 本地视觉不在 v1 范围（没有本地视觉模型时启用本功能即隐含接受截图上云，文档在此明示）。

## 4. 语义事件契约

- kind：`screen.observed`
- source_kind：`screen`
- dedupe_key：`screen:{16hex 感知哈希}`（同画面跨轮去重；管线另有 300s 窗口）
- evidence_ids：`[TimelineEvent.source_id]`（观察记录可回溯）
- attributes：`message`（话题句）、`display`
- expires_at：5 分钟（过期不补发）

## 5. 配置（config.screen_awareness）

| 字段 | 默认 | 说明 |
|---|---|---|
| enabled | false | 总开关，默认关闭 |
| interval_seconds | 60 | 15~600 |
| displays | [1] | 显示器编号列表，1=主屏；配置 [1,2,3] 覆盖三屏 |
| analysis_prompt | 内置 | 视觉分析指令前缀 |
| memory_enabled | true | memory_worthy 升级记忆 |
| proactive_enabled | true | notable 进主动管线 |
| unchanged_skip_threshold | 6 | 感知哈希汉明距离阈值（0~64） |

成本参考：60s 间隔 + 变化检测下，专注工作场景每小时通常只有个位数次云视觉调用；纯静态画面接近零调用。

## 6. Admin

「能力接入 → 屏幕感知」（`/screen-awareness`）：运行状态 Tab（开关/间隔/循环健康/各屏哈希与最近分析/冷却状态/最近错误）与观察记录 Tab（最近 50 条 screen.observed 摘要）。
