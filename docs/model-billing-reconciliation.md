# 模型费用与账单比较

账单比较为只读核对，报告标为 `operator_supplied_bill_unverified / V2`。金额一致只证明提供的两份数据一致，不能验证账单来自提供方，也不代表账户完整费用。报告不改动费用台账、价格快照或预算扣占，不会把未知用量变成零。它不是退款或重新结算接口。

## 获取本账户快照

登录用户调用 `POST /api/v1/runs/costs/snapshot`，请求包含带时区的 `period_start` 和 `period_end`。期间使用 UTC、开始包含/结束不包含，最多 366 天；仅导出该用户在期间内已登记的费用调用。超过 10,000 条明确拒绝，缩小期间再导出，不截断后声称完整。快照包含 call ID、端点名、请求回执标识、状态、币种和微单位扣占，没有提示/响应正文。快照是本次读取的状态，晚到 usage 可能改变下一次导出。

提供方账单须由操作员从授权账户取得，并映射成 `BillingEvidence` JSON：期间、`declared_complete`、最多 1,000 条 `lines`。每行是 `endpoint / provider_request_id / currency / billed_micros`。端点名必须匹配本地配置；跨账户/端点的同名请求不能混用。金额使用十进制整数字符串，一单位币种等于 1,000,000 微单位；不得浮点换算、隐式换汇或将账单总额自行平摊到请求。

此处的完整声明来自操作员，不代表提供方真实性。账单若只有月度总额、缺少请求标识或按 SKU 聚合，不应编造逐请求明细。提供方计费日期与本地准入日期可能不同，须先核对时区、跨日调用和覆盖区间；缺少记录只报告缺失，不推断没有发生费用。

## 比较与读取结果

`POST /api/v1/runs/costs/reconcile` 接受上述账单证据，同样只读当前登录账户台账。也可离线对已导出的两份文件比较：

```sh
uv run python server/scripts/reconcile_model_bill.py --ledger ledger.json --bill bill.json > report.json
```

CLI 无网络/数据库端口，只读取两个普通文件（每个不超过 2 MiB，拒绝符号链接和 FIFO）。输入错误只输出异常类别，不回显账单标识。退出 0 表示非空、声明完整且全部比较一致；1 表示差异、证据不足或空比较；2 表示输入无效。退出 0 仍为 V2，不能据此解锁未知扣占。

结果分类：一致、金额不符、币种不符、台账未知、回执歧义、缺失回执、只有台账、只有账单。对重复回执不选择其中一条、不求和、不去重；每条相关记录单独保留歧义，所以 counts 是比较条目数而非唯一调用数。未知台账即使占额碰巧与账单一致，也不变为已核实。

报告保留 call ID、币种/金额、分类、两份输入的规范化哈希；提供方请求标识只输出端点绑定哈希。行顺序不同仍可复算同一报告。报告不会持久化到系统数据库，保存文件须沿用操作员的账单访问权限。

## 合成演示

`docs/baselines/billing` 的 ledger/bill/report 全部是手工合成，不是真实账单。合成台账 100 微单位、合成账单 90 微单位，比较返回 `amount_mismatch` 和退出 1。不要将这两份文件导入真实账户，也不要将示例端点绑定真实模型。

尚未覆盖提供方签名/API 拉取、ASR/TTS/媒体费用、未登记历史调用、账户总额、税费/折扣/退款，以及旧备份缺失费用。真实账单核对必须另记授权账户、期间和证据，不能用合成演示代替。


## 单位报价底座

台账现支持明确的 request/image/second/character/byte 报价和数量，与 token 费用共享账户币种额度；费率及数量保留精确十进制。未知用量保持预留，明确迟到用量才可结算，价格估算不等同于账单。当前快照仍只输出已有的内容无关 ID/端点/币种/金额/状态字段，不将数量当作已核验的提供方使用证据。

这只是软件底座，ASR/TTS/媒体入口的实际单位规则和预算适配继续接入；合成数据库回归不能证明真实提供方费用、税费或完整账单。未执行生产迁移，也未获取真实账单。
