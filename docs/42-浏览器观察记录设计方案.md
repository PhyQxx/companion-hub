# 42 - 浏览器观察记录设计方案

> 状态：v1 全量已实现（P1/P2 于 2026-09-08，P3 于 2026-09-10）
> 相关：[38-屏幕感知与主动话题设计](./38-屏幕感知与主动话题设计.md)、[41-设备工具Token优化与MCP接入方案](./41-设备工具Token优化与MCP接入方案.md)、[31-记忆时间线与历史回溯设计](./31-记忆时间线与历史回溯设计.md)

## 1. 功能定位

补齐浏览器插件（Aria Browser Bridge）与桌面屏幕感知对等的**观察记录**能力：当前插件是纯被动设备，只有助手按需下发 `browser.current_tab.read` / `capture` 时才读取页面，读到的原文走 `EphemeralDeviceAssetStore` 阅后即焚，事后没有任何可回看的档案——管理后台「命令记录」里只有命令级台账，没有内容级摘要。

本方案新增 `browser.observed` 观察事件：中枢周期性读取浏览器当前标签页，经变化检测与 LLM 摘要后写入 Timeline，可选进入长期记忆与主动提醒，并在管理后台提供与「屏幕感知 / 观察记录」对等的两个查看页。

- **全量沉淀**：每份摘要写入 Timeline（`browser.observed`），可检索"我看了哪些网站"；
- **显著升级**：`memory_worthy` 的观察进入长期记忆（情景记忆、低重要度，对齐屏幕感知）；
- **主动话题**：`notable` 的观察构造 `SemanticEvent(kind="browser.observed")` 进入感知管线，经认知循环判定后投递。

## 2. 架构决策：Hub 拉取，而非插件推送

| | A. Hub 拉取（采用） | B. 插件主动推送 |
|---|---|---|
| 原理 | 服务端循环周期下发 `browser.current_tab.read`，复用现有命令通道 | 插件用 `chrome.alarms` 自行采样，新增 `observation.push` 帧 |
| 插件改动 | **零** | 新帧类型 + MV3 保活 + 设备端脱敏，改动大 |
| 安全模型 | 插件保持纯被动（只响应签名命令），与现有威胁模型一致 | 设备发起内容上行，隐私审面扩大 |
| 与屏幕感知一致性 | 完全同构（`screen.monitor` 也是每 tick 下发命令） | 异构，两套运维心智 |

方案 B 的唯一优势是不产生轮询命令记录，该缺点在 §10 三期用心跳指纹优化解决。

## 3. 数据流

```
BrowserAwarenessLoop (tick, 默认 60s, 15~600s 可配)
  ├─ 读 config.browser_awareness（每 tick 重读，支持热更新）
  ├─ DeviceTargetResolver.resolve(capability="browser.current_tab.read")
  ├─ gateway.issue(command="browser.current_tab.read", args={})
  │    → 插件回传 BrowserDocument JSON，资产 consume-on-read（原文即焚）
  │    → 隐私闸门：origin 限 http/https、blocked_hosts 精确匹配跳过、正文截断
  │    → 变化检测：sha256(origin + "\n" + title) 前 16 hex，与上次相同则跳过
  │    → LLM 文本摘要（LLMRouter 文本槽位）→ JSON {summary, notable, memory_worthy, topic}
  │    → TimelineStore.index_browser_observation（source_type=device, event_type=browser.observed）
  │    → memory_worthy → MemoryCandidate(EPISODIC, SYSTEM_EVENT, browser-v1) → MemoryIngester
  │    └→ notable → SemanticEvent(dedupe_key="browser:{hash}", salience=0.75, stable 10s)
  │         → PerceptionPipeline.submit → ProactiveDeliveryService.deliver
  └─ 连续 3 次失败 → 冷却 10 分钟（多设备 ambiguous 记 last_error 跳过）
```

## 4. 分步改动清单

### 4.1 配置节（`server/app/config/models.py`，`ScreenAwarenessConfig` 之后）

```python
class BrowserAwarenessConfig(StrictModel):
    """中枢周期浏览感知：插件端闸门（配对令牌、host 权限）不变。"""
    enabled: bool = False                     # 默认关，与屏幕感知一致
    interval_seconds: Annotated[int, Field(ge=15, le=600)] = 60
    analysis_prompt: Annotated[str, Field(min_length=1, max_length=1_000)] = (
        "概括用户当前浏览的网页内容，并判断是否值得记录或主动提醒。"
    )
    memory_enabled: bool = True
    proactive_enabled: bool = True
    max_text_chars: Annotated[int, Field(ge=500, le=30_000)] = 8_000
    blocked_hosts: Annotated[list[str], Field(max_length=200)] = []   # 精确主机名，大小写不敏感
```

`AppConfig` 加字段 `browser_awareness: BrowserAwarenessConfig = Field(default_factory=BrowserAwarenessConfig)`（`screen_awareness` 字段旁）。配置存储为整份 JSON，新字段带默认值即可平滑兼容；管理端已有防覆盖逻辑（ModelsView.vue 合并时保留未知节），无需迁移。

### 4.2 感知循环（新文件 `server/app/browser_awareness/loop.py` + `__init__.py`）

镜像 `screen_awareness/loop.py`，模块 docstring 写明隐私边界（对齐其三段式声明）：

- **协议重声明**：`DeviceGateway` / `ScreenTargetResolver` / 资产 store 协议在本模块重声明（模块自治风格，约 60 行重复；三处以上重复再抽 `app/awareness/shared.py`）。
- **常量**：`READ_COMMAND = "browser.current_tab.read"`、`ASSET_TTL_SECONDS = 30`、`WAIT_TIMEOUT_SECONDS = 31`、连续失败 3 次冷却 10 分钟。
- **变化检测**：屏幕用感知哈希，这里用 `sha256(f"{origin}\n{title}")[:16]`；同上次则跳过 LLM 与 Timeline 写入；dedupe key 复用该哈希。
- **分析器**：`LlmBrowserAnalyzer` 按 `LlmMeetingSummarizer` 模式构建（`build_router(config, secrets)` → `CompletionBackend.complete`），走**文本模型槽位**，不占视觉模型；prompt 复用 `analysis_prompt` 的 JSON 约定，`parse_analysis` 解析失败时全文当摘要、不记忆（行为与屏幕感知一致）。
- **隐私闸门**（LLM 调用前）：origin 非 `http/https` 跳过；`blocked_hosts` 精确匹配跳过（不记 error）；正文截断 `max_text_chars`。
- **文档校验**：对回传 JSON 用与 `tools/browser.py` 的 `BrowserDocumentPayload` 相同 schema 的本地模型校验。
- **记忆/主动分支**照抄 `_capture_display` 尾部：`MemoryCandidate(type=EPISODIC, content=f"[浏览观察 · {host}] {summary}", extractor_version="browser-v1", importance=0.3)`；主动事件 `SemanticEvent(kind="browser.observed", source_kind="browser", salience=0.75, stable_for_seconds=10)`。
- **LoopState**：单设备维度（无 display 概念），字段含 `last_origin / last_hash / last_analyzed_at / last_summary / consecutive_failures / cooldown_until / observations`。

## 5. 隐私与安全边界

1. **原文即焚**：页面正文走 `EphemeralDeviceAssetStore`（TTL 30s、consume-on-read、进程内存），分析后即消失；持久化的只有摘要文本 + origin + 截断标题。
2. **插件端闸门不变**：配对令牌签名帧、`optional_host_permissions` 用户授权、`restricted_page` 拒绝。
3. **Hub 侧总开关**：`browser_awareness.enabled=false`（默认）时循环空转不发任何命令；Admin 状态页可见循环健康。
4. **主机黑名单**：`blocked_hosts` 精确匹配（大小写不敏感），命中即静默跳过，建议使用方配置银行/登录页主机名。
5. **URL 降敏**：只存 origin，不存路径与查询串。
6. **主动提醒过认知循环**：`notable` 只构造感知事件，经 M3B 判定后才投递，不会直接推消息。

## 6. 与屏幕感知的形态差异

| 维度 | 屏幕感知 | 浏览感知（本方案） |
|---|---|---|
| 目标 | 每显示器一个状态 | 单设备单状态（无 display 概念） |
| 变化检测 | Pillow 8x8 感知哈希 + 汉明距离阈值 | sha256(origin+title) 精确比较 |
| 分析模型 | 视觉槽位（`analyze_vision`） | 文本槽位（LLMRouter complete） |
| 事件 | `screen.observed` | `browser.observed` |
| extractor | `screen-v1` | `browser-v1` |

## 8. 已知代价

1. **命令台账噪声**：每 tick 产生一条 `browser.current_tab.read` 记录（60s 间隔、设备在线时约 1440 条/天），与屏幕感知的 `screen.monitor` 完全一致，属既有行为；`idempotency_key` 生成时带 `browser-observe-` 前缀，便于后续在 DevicesView 命令记录页过滤。
2. **轮询成本**：变化检测在读取之后，稳态（页面不变）下仍每 tick 发一次命令；省略方案见 §10。
3. **多浏览器设备**：一期 `target=None`，多设备时 resolver 报 ambiguous → 记 `last_error` 跳过（与屏幕感知对多桌面设备的处理一致）；二期可加 `target_device` 配置。

## 10. 三期优化（2026-09-10 已实现）

1. **心跳指纹降本**：`DeviceHeartbeatFrame` 加可选 `tab_hint {origin, title}`（协议向后兼容）；插件仅在 Hub 于 `device.accepted` / `heartbeat.accepted` 帧声明 `observe_tab_hint` 时上报指纹（`buildTabHint` 只取 origin+标题，受限页面为 null）；循环每 tick 把开关回写网关，指纹与上次观察一致时跳过 read 命令与 LLM 分析——稳态零成本，指纹缓存掉线即清空。
2. **台账过滤**：DevicesView 命令记录页新增「隐藏感知轮询」开关（默认开启），按 `idempotency_key` 前缀 `screen-monitor-` / `browser-observe-` 折叠轮询命令。
3. **召回融合**：新增 `timeline/browser_recall.py`（`BrowserActivityRecallService`），拦"浏览/网页/网站/浏览器 + 总结词"意图，按站点 origin 聚合 `browser.observed` 分段注入聊天上下文（`【浏览活动回顾】`），decision_meta 记录 `mode=browser_activity`；聊天端可回答"我下午看了些什么网站"。
